# Сборка JAR через GitHub Actions

Сборка ещё НЕ запускалась на GitHub. Этот архив содержит исходники и настройку автоматической сборки, а не готовый JAR.

## Загрузка проекта
1. В GitHub создать пустой репозиторий, желательно приватный.
2. Распаковать архив. В корне репозитория должны оказаться build.gradle, settings.gradle, gradlew, папки gradle, src и .github. Не загружать ZIP как единственный файл и не помещать проект во вложенную папку.
3. Надёжный способ загрузить все файлы, включая скрытую .github и gradle-wrapper.jar: GitHub Desktop → File → Add local repository → выбрать распакованную папку → создать репозиторий в этой папке, если предложено → сделать первый commit → Publish repository. Если пустой удалённый репозиторий уже создан, можно сначала клонировать его через GitHub Desktop, скопировать в него содержимое проекта и сделать commit/push.
4. Не включать в репозиторий пароли, токены или личные файлы. Для этой сборки секреты не нужны.

## Запуск и результат
1. Открыть репозиторий → Actions → Build Forge mod. При необходимости разрешить Actions в репозитории.
2. Нажать Run workflow → Run workflow, либо дождаться сборки после первого push в main/master.
3. После успешного запуска открыть его страницу → Artifacts → legendary-frontiers-jar.
4. Скачать артефакт ZIP, распаковать его и взять файл .jar. Сам ZIP в mods класть нельзя.
5. Установить JAR в отдельный профиль Minecraft 26.3 / Forge 66.0.9. Сначала проверить в новом тестовом мире.

## Если запуск красный
Скачать build-diagnostics, распаковать build-output.log и прислать этот файл сюда. Если ошибка произошла до шага Build mod и артефакта нет, скопировать текст ошибки из упавшего шага.

Настройка Actions проверена только локально на синтаксис. Она не доказывает, что зависимости доступны или Java-код совместим с Forge 26.3. Успешную сборку и запуск в игре ещё необходимо подтвердить.
